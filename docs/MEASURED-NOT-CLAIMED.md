# Measured, not claimed: what x402's numbers taught us about responses

*An explainer. Last verified 2026-09-15. Every figure below is dated and linked; corrections welcome by issue.*

In September 2026 the agent-payments rail learned that its headline metric was not a measurement.
This note is about why that matters one layer down, at the level of a single API response, and
what a re-derivable hash does about it. It is written by the author of GVP, who runs one x402
service and is not neutral. The numbers are other people's.

## 1. The rail's counter was a claim

The public counter on x402.org showed the same four numbers for months. Daniel McGlynn checked it
repeatedly and wrote it up on 2026-09-06: "It shows 75.41M transactions, $24.24M in volume, 94.06K
buyers and 22K sellers. [...] I checked the page directly on August 27, on August 31, twice in the
first week of September, and again on the morning this went out."
([source](https://www.danielmcglynn.com/the-x402-counter-has-shown-the-same-four-numbers-since-march/))

When someone measured instead, the picture changed. Visa and Artemis published *Agentic Payments
from the Ground Up* in July 2026
([Visa](https://www.visa.com/en-us/thought-leadership/innovation/agentic-payments-from-the-ground-up)).
McGlynn's summary of the before-and-after: "roughly 178.3 million raw transactions and about $135.7
million in raw dollar volume [reduced] to 109.6 million transactions and roughly $15.0 million. That's
39% of transactions and 89% of dollar volume classified as wash, test or internal transfer rather
than someone paying for something." A Coinbase engineer is quoted in the same piece saying that 25%
to 30% of transactions "may have been generated by users trying to climb public leaderboards rather
than buying services they needed."

A directory that reads the chain directly, x402-list.com, reported on 2026-09-15 (its `/api/v1/stats`,
computed 07:25 UTC): 782 listed services, $98,370 settled in the trailing 30 days, 4,802,372
settlements, 4,675 distinct buyers, and a note that its own count is "a conservative undercount".
That is the difference between a number somebody publishes and a number anybody can recompute.

## 2. The same gap exists at the payment layer

A payment receipt proves that money moved. It does not prove the seller delivered. "When HTTP 402
Meets the Blockchain: Risks on Emerging x402 Payments" (Wang, Yang, Chen, Ji, Payer; USENIX Security
2026; [arXiv 2607.19545](https://arxiv.org/abs/2607.19545)) derives four attack vectors (Free Shopping,
Asset Theft, Service Denial, Gas Abuse). One merchant-side Free Shopping case: a payment that
verifies but never settles can still leave a cached, replayable answer behind. x402toll.com had exactly that hole
until the paper was read against the code in August 2026; the fix ships with a regression test that
replays the attack. Settlement is measurable on-chain. Delivery is not.

## 3. And it exists at the response layer, which nobody measures

Suppose settlement is real and delivery happened. The buyer holds a JSON body. What does it prove?

- A **signature** proves the issuer emitted those bytes. It does not prove the bytes answer the
  question that was asked, and a dishonest issuer signs whatever it likes.
- A **log line** proves the issuer wrote a log line.
- A **claim** ("verified", "audited", "deterministic") proves nothing, for the same reason the counter
  proved nothing.

The only thing that survives the counter lesson is a value anyone can recompute from public inputs.

## 4. What a re-derivable hash gives you, exactly

Golden-Vector Provenance defines one field:

```
responseHash = "sha256:" + hex(SHA-256(JCS({ endpoint, inputs, result, method, dataVintage })))
```

JCS is [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785), so any conforming library produces the
same bytes. The five members are the closed rule set `GVP-FixedPoint/1`
([spec §2.1](../spec/gvp-0.2.md)). A verifier who holds the response and knows what they asked
recomputes the hash in one line and compares. No key. No callback. No trust in the issuer, in a
directory, or in a counter.

What it proves: the answer is **unaltered** (the bytes you hold are the bytes the hash was computed
over) and **re-derivable** (the question and the answer are bound together; a seller cannot drop the
inputs and stay consistent, because the member set is a spec constant, not a self-declared list).

What it does not prove: that the answer is **correct**. Correctness is a separate claim, checked
separately. For x402toll.com that is a free golden vector per endpoint with published inputs, expected
result, and expected hash. The spec says this boundary out loud
([§1](../spec/gvp-0.2.md), [§2.1.2](../spec/gvp-0.2.md)), because a provenance scheme that implies
correctness is another claim.

## 5. Where this stands, stated the same way

- Spec, JS and Python references, and eight published vectors: this repository, v0.7.0, Apache-2.0
  code / CC-BY-4.0 spec.
- One external production implementation: the SCVD conformance desk merged a `responseHash`
  re-derivation check on 2026-08-27 on its own RFC 8785 implementation
  ([PR #270](https://github.com/seancrecord/scvd-general-store-repo/pull/270)).
- Three independent parties reproduced published vectors byte-for-byte with their own code:
  [whawk46/x402-jcs-crosscheck](https://github.com/whawk46/x402-jcs-crosscheck) (24/24), the SCVD
  desk's own canonicalizer (its self-proof gate), and giskard09's 2026-09-15 reconstruction of the
  x402 extension's normative worked vector with a third-party RFC 8785 library (review on
  [#3304](https://github.com/x402-foundation/x402/pull/3304)). Reproduction is not adoption.
- A PR carrying the field as an x402 extension is open at
  [x402-foundation/x402#3304](https://github.com/x402-foundation/x402/pull/3304): one reviewer
  approval, waiting on a maintainer, not merged.
- Live issuer: x402toll.com, 59 endpoints.

Each of those lines is checkable from a public surface. That is the point.
